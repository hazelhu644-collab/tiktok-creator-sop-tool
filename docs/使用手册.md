# 使用手册

面向使用这个工具的运营人员。按实际做事的顺序写，不是按模块罗列。

```
准备产品（每个新品一次）
    │
    ▼
开始一轮 ──▶ 每天跑队列 ──▶ 更新进展 ──▶ 结束一轮
    ▲                                        │
    └────────────────────────────────────────┘
              下一轮可以再找上一轮的达人
```

产品配置一次，后面四步一轮一轮地转。

---

## 一、准备产品

**每个新品做一次。** 这一步填的拍摄要求，后面所有英文话术都会自动引用；填得越具体，生成的话术越准。

### 1. 建产品，顺手建店铺

`设置 → 新增产品`

先填产品名，再填店铺 / 品牌。**输入一个没用过的名字，就会创建这个新店铺**——不需要先去别的地方建。

### 2. 填拍摄要求

`设置 → 产品项目设置`

产品卖点、视频数量、单条时长、必须展示的画面、挂车和 tag 要求。

不想一个个填，就展开「辅助生成拍摄要求」，写几个关键词后点 **用 AI 直接生成草稿**，看着满意再点「应用到当前产品项目」。不想调 AI 就点「生成可复制提示词」，自己贴到 ChatGPT。

> **草稿不会自动写入。** 一定要点「应用」才生效；生成得不好，点「放弃这版草稿」。

---

## 二、开始一轮 ↻

`达人数据库 → 导入 Excel / CSV`

也可以点「新增达人」一个个加。导入后**先看一眼摘要**：

```
识别到 16 列，其中 16 列已匹配。
```

如果出现「未识别的列：XXX」，说明那一列没进来。

表头带标题行、有空格、GBK 编码、数据在第二个 sheet——这些都会自动处理，不用迁就工具。

---

## 三、每天跑队列 ↻

**这是主战场。** 每天开工只需要打开今日工作台，达人已经排好序，从上往下做。

### 照顺序来，不用自己判断谁更急

| 优先级 | 触发原因                          |
| ------ | --------------------------------- |
| 最高   | 达人已回复，等待处理              |
| 最高   | 产品已送达 9 天，视频进度仍为 0/2 |
| 高     | 已发布 1 条，剩余 1 条待履约      |
| 中     | 样品运输中，提前沟通拍摄要求      |

每行都写了**为什么是这个优先级**，不用回头翻表格核对。

### 生成 → 复制 → 去 TikTok 发 → 回来标记

1. 点「生成话术」，出来一段英文
2. 点「复制英文话术」，去 TikTok 发给达人
3. 回来点 **标记为已发送**

> **第三步别漏。** 它会更新最近联系日期、跟进次数、下次跟进日期，这个达人今天就从队列里消失。不点的话，明天他还会再出现一次。

### 达人回复了

把回复粘进「达人回复原文」，在「我想回复的重点」写上你的意思——**中文就行**，比如「确认周五发布，提醒挂车」。然后点「根据上方重点生成英文回复」。

> 需要 AI 的只有两处：翻译达人回复、生成个性化回复。**不配 API key 也能正常用**，本地话术库照常工作。

---

## 四、更新进展 ↻

事情有变化时去对应模块改。改完状态，今日工作台的优先级会自动重算——不需要手动调整谁排前面。

- **样品追踪** —— 物流状态、到货日期
- **达人数据库** —— 视频进度改成 `1/2`、`2/2`
- **内容审核** —— 视频发出来后对着清单验收
- **投流素材库** —— 挑出能拿去投流的 UGC

---

## 五、结束一轮 ↻

### 一次性收尾

`设置 → 结束第 N 轮`

点之前会先告诉你结果：

```
共 12 位达人，其中 3 位已完成、9 位未完成。
全部会被归档（不会删除），未完成的会标红。
之后新增的达人进入第 2 轮。
```

### 再开下一轮

回到「开始一轮」导入新一批。**上一轮合作过的达人可以再加进来**，不会被当成重复——系统会提示「该达人在第 1 轮合作过，历史记录仍保留」。

两条记录并存，所以能对比同一个达人在不同轮次的表现。

### 回看历史

`轮次复盘`

每一轮谁完成、谁没完成、哪些达人跨轮出现过，随时能查。未完成的在达人数据库里标红。

---

## 出问题怎么查

**导入后达人名变成了 `Creator 1`、`Creator 2`**
说明「达人账号」这一列没认出来。看导入摘要里的「未识别的列」。

**提示「没读到达人数据」**
报错会说清楚它读了哪个 sheet、表头在第几行、识别到几列。照这三个信息核对表格。

**队列里某个达人一直不消失**
多半是发完消息忘了点「标记为已发送」。

**想演示给别人看**
网址后面加 `?demo=1`。演示模式用假数据，**不读也不写真实记录，不消耗 API 额度**，刷新即清空。

## 模块速查

| 模块         | 什么时候用                               |
| ------------ | ---------------------------------------- |
| 今日工作台   | 每天开工第一个打开，处理今天要联系的达人 |
| 达人跟进中心 | 和工作台同一个队列，换个视图看           |
| 达人数据库   | 导入导出、搜索筛选、批量改状态           |
| 轮次复盘     | 回看历史轮次，找出没完成的达人           |
| 样品追踪     | 物流和到货跟进                           |
| 沟通话术模板 | 维护常用英文话术，套用到具体达人         |
| 内容审核     | 视频发出来后照清单验收                   |
| 投流素材库   | 挑出可投流的 UGC 素材                    |
| 设置         | 产品项目、拍摄要求、结束轮次、清空数据   |

---

数据保存在当前浏览器，不上传服务器。换浏览器或清缓存前，先在达人数据库导出 CSV。
